**CodeAtlas 设计说明 v7**

**核心原则**

辅助工具，不是基础设施。不参与构建、版本控制、测试或任何项目流程。唯一职责是帮 LLM 用最少的 token 理解代码结构。索引可随时从源码重建，丢了不影响项目。没有配置文件也能用默认规则运行。

这是一个 LLM-oriented code atlas，不是 static analysis tool。

三条架构原则：

一、采集层信息不丢失。所有从源码中可提取的结构关系都完整记录，不在采集阶段做简化或聚合。

二、渲染层负责 token 优化。对 LLM 的简洁输出通过渲染层完成，包括路径压缩、关系聚合、信任域折叠。底层数据模型不为输出简洁而硬砍信息。

三、系统只描述结构，不解释语义。不做类型推断，不做语义分析，不猜测运行时行为。只忠实记录源码中显式存在的结构和关系。

系统只做三件事：描述包含关系，描述实体间的连接关系，管理信任域。

**设计边界**

以下是系统定位上不做的，不是能力不足的妥协，而是刻意的设计选择：

不做精准 call graph。不追踪精确调用路径和参数传递。

不做类型推断。不分析运行时类型，不解析动态分派。类型信息只取源码中显式标注的部分。

不做模板实例展开。C++ 模板只记录签名含模板参数列表，不展开特化。

不做宏展开。复杂宏不处理。宏定义中的全局常量和类型别名归入全局变量。

不做 LSP 级语义分析。不提供补全、重命名、重构等功能。

**符号定义边界**

以下明确哪些 AST 实体算 symbol：

是 symbol：顶层函数、类、结构体、类方法、全局变量（仅简单赋值）、enum、类型别名。

不是 symbol：嵌套函数、lambda、列表推导式作用域、装饰器生成的包装函数、dataclass field、property、import alias、类属性。

**符号标识**

每个符号有一个稳定的 signature_hash 作为跨 rebuild 的标识。生成规则按语言分别定义。

Python：hash(language + module_path + lexical_container + symbol_kind + symbol_name + arity)。参数名不参与哈希，参数个数参与。

C/C++：hash(language + qualified_name + symbol_kind + parameter_type_list)。参数名不参与哈希。

qualified_name 构建规则写入语言映射层。Python 为 module.class.method，C++ 为 namespace::class::method。

数据库主键用自增整数做内部引用，signature_hash 做 rebuild 时的匹配键。rebuild 时优先用 signature_hash 匹配，继承信任等级。匹配不到的新符号默认 low。

**符号类型枚举**

symbol_kind 取值：module、namespace、class、struct、function、method、variable、enum、alias。

覆盖 Python / C++ / 后续主流语言。

**符号可见性**

symbols 表预留 visibility 字段，默认 null。

MVP 阶段只做最保守的标记。Python 对 _ 前缀标记 private，对 test_ 模块下的符号标记 test。其他情况留 null，不猜测。C++ 阶段再补 public / private / protected 解析。

取值：public、internal、private、test、null。

**内部架构**

三层结构。

存储层。路径用树管理，每个节点只存自身名称，完整路径由根到叶遍历隐式得出。符号挂在文件节点上，记录元信息和文件指针。文件指针拆为独立字段：声明位置（decl_file_id / decl_start / decl_end）和定义位置（def_file_id / def_start / def_end），Python 中两组相同，C/C++ 中可能不同。包含关系体现为树结构本身。

连接关系采集到方法级，始终完整记录，不做可选。symbol 级连接和 file 级连接分表存储。symbol edges 带轻量 edge_kind 字段。file edges 只记录 import/include。

namespace 建模为符号集合，通过 namespace_members 关联，支持跨文件分布。

SQLite 存储。content_hash 使用 xxhash64，速度优先，不需要加密安全性。

数据库结构：

```
files(
  id INTEGER PRIMARY KEY,
  path TEXT UNIQUE,
  parent_dir TEXT,
  language TEXT,
  in_workspace INTEGER,
  content_hash TEXT,
  parse_status TEXT,
  last_indexed_at TEXT
)

symbols(
  id INTEGER PRIMARY KEY,
  name TEXT,
  qualified_name TEXT,
  signature_hash TEXT,
  symbol_kind TEXT,
  language TEXT,
  file_id INTEGER,
  parent_symbol_id INTEGER,
  decl_file_id INTEGER,
  decl_start INTEGER,
  decl_end INTEGER,
  def_file_id INTEGER,
  def_start INTEGER,
  def_end INTEGER,
  trust_level TEXT,
  trust_source TEXT,
  visibility TEXT,
  updated_at TEXT
)

edges(
  id INTEGER PRIMARY KEY,
  src_symbol_id INTEGER,
  dst_symbol_id INTEGER,
  edge_kind TEXT
)

file_edges(
  id INTEGER PRIMARY KEY,
  src_file_id INTEGER,
  dst_file_id INTEGER,
  edge_kind TEXT
)

namespaces(
  id INTEGER PRIMARY KEY,
  name TEXT,
  qualified_name TEXT,
  parent_namespace_id INTEGER
)

namespace_members(
  namespace_id INTEGER,
  symbol_id INTEGER
)

trust_log(
  id INTEGER PRIMARY KEY,
  timestamp TEXT,
  target TEXT,
  old_level TEXT,
  new_level TEXT,
  trust_source TEXT
)
```

edge_kind 枚举。symbol 级：call、use_type、inherit、instantiate、reference。file 级：import、include。保持小而稳定，不继续细分。

查询层。接收查询指令，遍历存储层，执行过滤、信任域控制、展开深度限制，返回结构化数据。不关心输出格式。

渲染层。将结构化数据转为 LLM 友好文本。路径压缩：查询结果共享公共前缀时提取前缀，后续用相对路径；结果分散时用完整相对路径。Level 0 渲染时自动将实体级连接聚合为模块/namespace 级依赖。Level 2 默认将方法级连接聚合为类级，用户可请求方法级展开。MVP 只实现紧凑文本格式。

渲染输出示例：

Level 0 overview（file 视图）：

```
[src/auth/] -> [src/db/], [src/crypto/]
[src/api/]  -> [src/auth/], [src/models/]
```

Level 0 overview（logic 视图，C++）：

```
auth:: -> db::, crypto::
api::  -> auth::, models::
```

两种视图语义严格分离。file 视图只基于 file_edges，logic 视图只基于 symbol edges 聚合，不混算。

Level 1 inspect：

```
@ src/auth/

[handler.py:42-67] authenticate(credentials: Credentials) -> Result
[session.py:10-35] SessionManager
  members: login(user: User) -> Session
           logout(session: Session) -> None
```

Level 2 连接关系（默认类级聚合）：

```
@ src/auth/

[handler.py] authenticate
  -> [../db/query.py] UserDAO
  -> [../crypto/hash.py] verify_password

[session.py] SessionManager
  -> [handler.py] authenticate
  -> [../db/query.py] UserDAO
```

Level 2 连接关系（方法级展开）：

```
@ src/auth/

[session.py] SessionManager
  .login -> [handler.py] authenticate
  .login -> [../db/query.py] UserDAO
  .logout -> [../db/query.py] UserDAO
```

search 结果：

```
search("authenticate")

#42 [src/auth/handler.py:42-67] authenticate(credentials: Credentials) -> Result  [low]
#58 [src/auth/session.py:28] SessionManager.authenticate  [low]
#91 [lib/oauth/client.py:15] OAuthClient.authenticate  [high]
```

结果带 #id 标识，低信任排前面。后续命令可直接用 #id 引用。

**功能**

语义索引构建。用 Tree-sitter 解析工作区内源码。提取模块、类、结构体、函数、方法、全局变量、enum、类型别名的定义及层级包含关系。提取实体间连接关系，采集到方法级，带 edge_kind。import/include 关系记录为 file → file 粒度，单独存储。不复制源码，只记录元信息和文件指针。

Python 解析范围：module、class、top-level function、class method、global variable（仅简单赋值）、import / from import。不碰嵌套函数、lambda、推导式作用域、装饰器语义效果、metaclass 行为、动态属性注入。

连接关系提取规则。function/method 体内出现调用顶层函数、实例化类、使用类名作注解或构造、调用导入对象，则记边。类级连接由方法级边聚合得到，不直接从类体扫描。模块级连接仅来自 import。

排除规则使用 .codeatlas.yaml 的 exclude 字段，语法兼容 glob 模式，不读取 .gitignore。

语言适配通过映射层实现：每种语言一份配置，定义顶层实体对应的 AST 节点类型、模块边界规则、import/include 解析方式、qualified_name 构建规则、signature_hash 生成规则。新增语言只需新增映射。

C/C++ 特殊处理。头文件与实现文件通过 qualified_name + 参数类型列表匹配，合并为同一符号，声明和定义位置分别记录。匹配失败时标记为 declaration_only 或 definition_only。namespace 建模为符号集合，支持跨文件分布。前向声明关联到实际定义，不重复记录。#include 记录为 file → file 依赖。模板只记录签名含模板参数列表。C++ 支持目标为"可用但保守的索引"，不承诺完整语义一致性。

多层级展开。Level 0 模块/namespace 间依赖关系。file 视图由 file_edges 直接得出，logic 视图由 symbol edges 聚合。Level 1 模块内顶层实体签名和类型定义，不含实现。Level 2 实体间连接关系，默认渲染为类级聚合，可请求方法级展开。Level 3 具体源码，通过文件指针动态读取。

信任域管理。每个符号或路径有信任等级（high/low）。高信任只暴露签名，查询时自动折叠。低信任默认展开到更深层级。默认规则：工作区内代码 low，工作区外依赖 high。信任等级变化纯由指令驱动，系统只执行和记录。

trust_source 区分信任来源：default（系统规则）、config（来自 .codeatlas.yaml）、explicit（CLI trust 命令）、inherited（rebuild 继承）。变更日志记录时间、目标、旧等级、新等级、来源。

可达性分析（可选）。入口点为可选配置。配置时 overview 标记可达/不可达，unreachable 命令可用。未配置时不可用。

**配置**

可选的 .codeatlas.yaml：

```
workspace: ./
language: auto
entry: src/main.py:main  # 可选
trust:
  high:
    - numpy
    - torch
    - src/utils/stable_module.py
  low:
    - src/experimental/*
exclude:
  - "*.generated.py"
  - build/
  - data/
  - __pycache__/
  - "*.pyc"
```

没有此文件时自动检测语言，全部走默认规则。

**对外接口**

所有接受 symbol 参数的命令同时支持两种定位方式：#id（如 #42，使用 search 结果中的标识）和 qualified_name（如 src.auth.handler.authenticate）。有歧义时列出候选让用户选择。

CLI 命令：

```
codeatlas init [--workspace] [--config]
codeatlas overview [--filter] [--view file|logic]
codeatlas inspect <target> [--level] [--max-items] [--force-expand] [--detail method]
codeatlas trace <target> [--direction forward|backward|both]
codeatlas search <query> [--exact] [--kind] [--path]
codeatlas read <symbol> [--part declaration|definition]
codeatlas rebuild [path]
codeatlas trust <target> <level>
```

`init` 首次解析建索引。若索引已存在则行为等同 rebuild。

`overview` 返回 Level 0 模块依赖图。filter 限定子目录或 namespace 范围。view 严格分离：file 只基于 file_edges，logic 只基于 symbol edges 聚合。若配置入口点则标记可达性。

`inspect` 返回指定模块、namespace 或类的信息。level 控制展开深度，默认 Level 1。max_items 限制返回符号数量。高信任节点自动折叠，force_expand 覆盖。detail=method 时 Level 2 展示方法级连接而非类级聚合。target 支持文件路径、namespace 路径或 #id。

`trace` 返回基于实体连接关系的邻域查询。MVP 阶段限制 depth=1，不支持多跳。direction 支持 forward、backward、both。高信任节点处自动停止展开。

`search` 在符号表中检索匹配符号。exact 精确匹配或子串模糊匹配，默认模糊。kind 按 symbol_kind 过滤。path 按文件路径过滤。返回匹配符号列表，带 #id、路径、签名、信任等级，低信任排前面。

`read` 通过文件指针动态读取指定符号源码。part 可选 declaration 或 definition，默认 definition。

`rebuild` 重新解析指定文件或整个工作区。通过 signature_hash 匹配已有符号，继承信任等级和 trust_source。新符号默认 low / default。支持单文件粒度。

`trust` 变更信任等级，trust_source 标记为 explicit，记录变更日志。

**实现方案**

语言：纯 Python。最终通过 Nuitka 编译为原生二进制发布。若遇兼容性问题退回 PyInstaller。

解析：Tree-sitter Python 绑定 + tree-sitter-python 和 tree-sitter-cpp 语法包。

CLI 框架：typer。

存储：SQLite 单文件数据库。

项目结构：

```
codeatlas/
  cli.py              # 入口，typer 命令定义
  config.py           # .codeatlas.yaml 加载与默认规则
  parser/
    base.py           # 解析器抽象接口
    python.py         # Python 语言映射与 signature_hash 规则
    cpp.py            # C/C++ 语言映射与 signature_hash 规则
  storage/
    db.py             # SQLite 操作
    path_tree.py      # 路径树
  query/
    overview.py
    inspect.py
    trace.py
    search.py
    read.py
  trust/
    manager.py        # 信任域管理与日志
  render/
    compact.py        # 紧凑文本渲染，路径压缩，关系聚合
```

**开发顺序**

第一阶段：parser + storage。只针对 Python，验证 Tree-sitter 解析、符号提取、方法级连接关系提取、SQLite 存储。验证 Nuitka 打包 Tree-sitter C 扩展。

第二阶段：overview + inspect + search + read + 渲染层。此阶段完成即可实际测试 CodeAtlas 对 vibe coding 的帮助。

第三阶段：trace（depth=1）、trust、rebuild。补全剩余命令。

第四阶段：C/C++ 支持。新增 cpp.py 语言映射，实现声明/定义合并、namespace 建模。目标为可用但保守的索引。

第五阶段：二进制打包与发布。

**MVP 范围**

前三阶段完成即为 MVP。Python 单语言。Tree-sitter 解析。SQLite 存储。init、overview、inspect、search、read、trace（depth=1）、trust、rebuild 共八个命令。紧凑文本渲染。入口点和可达性为可选。

**后续方向**

C/C++ 支持（第四阶段）。更多语言（新增 Tree-sitter 映射）。MCP Server 封装对接 AI 工具链。增量更新。更多渲染格式。信任等级细化。trace 多跳支持。visibility 完善。
